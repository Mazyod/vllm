## Configuration correction and provenance

The first development run passed phase 2 and the performance probes, but
phase 4 R3 failed: upstream #52998 enabled standalone FlashInfer all-reduce
independently of `disable-custom-all-reduce` and `fuse_allreduce_rms: false`.
The log showed `FLASHINFER,PYNCCL` dispatch, with TRT-LLM fallback after
NVSwitch multicast was unavailable. R3 explicitly excludes this path.

The controller and model processes were stopped after that finding, preserving
the captured receipts and boot log. Behavioral failures recorded during this
interruption are not additional model regressions. The rental and model cache
were retained.

The six affected TP2 profiles now set `VLLM_ALLREDUCE_USE_FLASHINFER=0`.
Their engine YAML bytes are unchanged. A fresh run executed phase 4 first to
verify the correction, then phase 3; it exited 0 with all 35 results passing.
Every corrected TP2 boot log, including the performance controls, passed R3
with the optimized paths absent. The shipping logs report `PYNCCL` only.

Phase 2's 15 results were retained only after verifying that its profile
metadata, engine digests, environment values, and image were unchanged.
Together these cover all 50 declared probes without substituting the initial
FlashInfer performance values for the corrected configuration.

## Deployment requirements and limitations

Apply the [fleet environment](../fleet.yaml) as well as the engine YAML:

```yaml
VLLM_USE_V2_MODEL_RUNNER: "0"
VLLM_ALLREDUCE_USE_FLASHINFER: "0"
```

The first setting preserves the tested V1 runner. Gemma Hopper + FP8 still
crashes under V2 with the SM90 FlashInfer sliding-window guard, and v0.29.0
now defaults to V2. The second setting preserves the tested TP2 collective
path. Keep the existing custom-all-reduce and RMS-fusion workarounds too.
Retire the new collective opt-out alongside those workarounds only through
the ancestry and real-traffic retirement protocol in `FORK.md` and `LESSONS.md`.

`qwen-tp2-noflags` again served despite declaring `boot_crash`. Its R5 probe
tests boot only; this does not justify removing the workarounds. Qwen's B2
checks for FSM HTTP failures with a short token budget, not completion of every
tool call. B5 remains audio request validation and survival: the FP8 Gemma
checkpoint rejected all 12 audio requests because it has no audio tower.

Gemma's corrected startup logged nonfatal safetensor metadata fetch timeouts;
startup continued and all its probes passed. This is separate from the absent
grammar errors.

The versioned promotion targets this gated digest. `latest` remains on
v0.28.0 pending confirmation that deployment applies the required environment.

## Cost, teardown, and software

One watched development rental was used throughout. The envelope was $5/hour,
a two-hour hard cap, and $12 including transfer allowance. Actual compute and
storage rate was $4.05/hour; the session lasted 117.0 minutes, approximately
$7.90 for compute and storage, excluding transfer fees.

Model staging began with an empty cache and received 64,330,314,128 bytes in
73.4 seconds (7,010 Mbit/s). This measures staging traffic, not the preceding
image pull. Checkpoint caches were reused across every subsequent launch;
compilation caches were retained. Evidence was collected before destruction,
and the provider confirmed that the instance and its label were gone.
The external label watchdog subsequently reported confirmed teardown too.

Software: vLLM 0.29.0, PyTorch 2.13.0+cu130, Transformers 5.16.1,
XGrammar 0.2.3, FlashInfer 0.6.18, PyAV 18.1.0, SoundFile 0.14.0.
CPU preflight printed `PREFLIGHT GREEN` (568 passed, 6 skipped, full mock gate).
All nine engine configurations passed the release's real parser on CPU and
on Hopper. Candidate image CI, alignment, and pre-commit checks passed.
