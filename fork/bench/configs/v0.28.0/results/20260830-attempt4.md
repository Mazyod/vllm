## Recorded expectation mismatches (not gated)

1. `gemma-v2-spec-kv-dtype` is declared `serves` and crashed at boot:
   `NotImplementedError: FlashInfer backend on SM90 currently crashes with
   sliding-window attention layers`. The v0.27.1 run crashed on the same line;
   the expectation has been wrong since then and only became visible when the
   report grew a mismatch table. **Decision (2026-08-30): retire the profile.**
   The arm existed to test whether a draft `kv_cache_dtype: auto` avoids the
   V2 + kv-fp8 crash; two releases say it does not (backend selection is
   unaffected), and `gemma-v2-kvfp8` already records that crash. Drop the
   profile and `engine/gemma-tp1-v2-spec-kv-dtype.yaml` from the next release
   directory (this one is frozen by this run).
2. `qwen-tp2-noflags` is declared `boot_crash` and **served** — the arm that
   omits both PCIe all-reduce workarounds (`disable-custom-all-reduce`,
   `fuse_allreduce_rms: false`) no longer crashes on v0.28.0. R5 is a boot-only
   probe, so this is not evidence the workarounds are safe to drop; retire
   them only through the ancestry protocol (LESSONS.md rules 8–11). The
   shipping `qwen-tp2.yaml` keeps both flags.

## Operational caveats

1. The fp8+spec Gemma arm still has a long first-request stall after boot:
   TTFT p99 8.69 s (10.74 s on v0.27.1). Warm the pod before it joins the
   balancer.
2. The image carries no dependency pin any more: the `transformers==5.14.1`
   pin that v0.27.1 needed to boot Gemma-4 is gone (#49797 is in v0.28.0), and
   the candidate resolved transformers 5.15.1. Gemma-4 booted and served on it
   in every profile above.
3. B5 passes as request validation only: the FP8 Gemma checkpoint ships
   `audio_config: null`, so all 12 audio requests are cleanly rejected and the
   probe asserts survival, not audio inference.
